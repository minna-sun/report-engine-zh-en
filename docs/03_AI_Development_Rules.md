# 03. 人机协同开发纪律 (AI Development Rules)
为了确保 AI 生成的代码质量可控、不产生屎山、不偏离架构，项目制定了极其严苛的 AI 开发纪律。

## 1. 核心纪律

### 1.1 走一步验收一步

- Agent 必须按顺序逐模块生成。每完成一个模块，**必须暂停**并等待人类验收。
- 严禁连续生成多个模块后统一验收。
- 验收通过后，由人类手动确认"备份当前版本"，方可进入下一个模块。

### 1.2 200 行硬约束

- 单模块代码**不得超过 200 行**（含空行和注释）。从根本上规避大模型上下文超限风险。
- 超过 200 行时，Agent 必须立即暂停，说明原因并申请拆分，严禁未经人类确认自行超出。

### 1.3 已验收模块只读

- 已通过验收并完成备份的模块视为"只读"。
- Agent 在后续开发中**不得主动修改**已验收模块的代码。
- 禁止：为修当前模块的问题而"顺手优化"已验收模块。

## 2. 技术栈统一约束

- **Excel 操作**：统一使用 `openpyxl`，跨平台、免 Office 依赖。
- **Word 操作**：通过 `DocumentEngine` 抽象层，**严禁**在业务层（Processor / Strategy）直接导入 `python-docx` 或 `lxml`。
- **路径管理**：所有文件路径必须从 `config.yaml` 读取，**禁止硬编码**绝对路径。
- **异常处理**：所有外部依赖（文件读取、Excel / Word 操作）必须使用 `try-except` 包裹，并抛出项目自定义异常（如 `WordOperationError`），禁止未捕获异常导致程序崩溃。

## 3. 验收标准（一票否决项）

- **资源释放**：涉及 Word 引擎的模块，`close(doc)` 必须在 `finally` 块中执行。任何异常路径都必须能释放资源。
- **容错机制**：单个章节执行失败，不得中断整份报告生成，必须在日志中记录错误并继续。
- **结论独立**：章节执行失败不影响最终报告结论，最终结论只依赖 `test_result` 字段判定。
